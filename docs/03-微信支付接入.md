# 微信支付承诺金接入

## 当前实现

```text
小程序 wx.login
  → POST /api/wechat/login
  → code2Session 得到 OpenID
  → POST /api/wechat/pay/deposit
  → 服务端调用 /v3/pay/transactions/jsapi
  → 小程序 wx.requestPayment
  → POST /api/wechat/pay/notify
  → 验签 + AES-256-GCM 解密 + 幂等入账
  → 周期结算
  → POST /internal/wechat/refund
  → /v3/refund/domestic/refunds 原路退款
```

服务端代码在 `server/`，小程序调起代码在 `miniapp/services/payment.js`。

## 需要配置

复制 `.env.example` 为 `.env`，填入：

- `WECHAT_APP_ID` / `WECHAT_APP_SECRET`
- `WECHAT_MCH_ID`
- `WECHAT_MCH_SERIAL_NO`
- `WECHAT_MCH_PRIVATE_KEY`
- `WECHATPAY_PUBLIC_KEY_ID` / `WECHATPAY_PUBLIC_KEY`
- `WECHATPAY_API_V3_KEY`
- `WECHAT_NOTIFY_URL`
- `WECHAT_REFUND_NOTIFY_URL`
- `INTERNAL_CRON_SECRET`

私钥、API v3 Key 和 AppSecret 只能放在服务端密钥管理中，不能提交 Git、不能写进小程序。

## 上线前还必须补的生产能力

当前仓库把支付协议、签名和回调链路做完整，但订单存储为进程内适配器。真实收款前必须替换为事务数据库，并补齐：

- `out_trade_no` 唯一索引；
- 支付回调事件唯一索引和幂等更新；
- 回调缺失时主动查单；
- 结算任务锁与重复退款保护；
- 每日交易账单/退款账单对账；
- 失败判定宽限期、申诉冻结和人工退款；
- 金额永远由服务端约定表读取，不能相信客户端传值。

代码已经做到最后一项：小程序只发送 `commitmentId`，金额由服务端 `server/commitments.mjs` 决定。

## 为什么不能直接承诺“自动扣款已跑通”

常规小程序支付需要用户在微信收银台确认。预约扣费需要额外的委托代扣权限、模板和运营评估，且官方当前仍标记灰度；每个预约商品还要单独授权、提前预约并发送预扣费通知。未打卡是一种用户行为结果，与官方所述预约购买场景并不等价。

所以本工程真实跑通的是普通小程序支付和退款的技术道路；在没有商户资质与真实密钥时，不会伪造支付成功。

## 本地验证

```powershell
npm test
npm run server
```

`npm test` 会验证：

- RSA-SHA256 签名与验签；
- 微信支付 API v3 回调资源的 AES-256-GCM 加解密。
