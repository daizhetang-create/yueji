# 约己 V0.3｜共同约池与设计端 AI 反向审查任务书

> 这不是一份“请帮我美化”的需求。你的任务是先逆向理解当前产品，再指出它为什么还不够有趣、不够像一款成熟 App，以及哪些设计会破坏它。

## 0. 当前产品一句话

约己把一个人真正想长期做的事，缩成今天可完成的动作；用户自愿支付一笔小额七日承诺金，先按完成份额守住自己的本金，完整履约后再获得共同奖励资格。

产品护栏：**约己奖励认真，不奖励下注。钱让行动产生连接，但不能让产品变成赌输赢。**

## 1. V0.3 已经发生的迭代

| 旧版本 | V0.3 | 为什么这样改 |
|---|---|---|
| 每项日常任务都显示“承诺 ¥9.9” | 承诺金只属于七日计划，日常任务卡删除错误金额 | 避免用户误以为每天、每项都会扣款 |
| 打卡只有完成/未完成 | 完成后出现一个很轻的“记一下”，用户主动点击才打开随记 | 反馈是用户行为，不是产品强迫完成的第二个任务 |
| 新增任务只有固定模板 | 保留一触即加模板，同时允许编辑名称、截止时间、每周出现日和自定义目标 | 自主选择有利于长期坚持，但编辑不能增加启动阻力 |
| 先强迫选择“验证/确定” | 默认一切都是确定目标；“七天验证”降为底部次级入口 | 不让小概率需求成为主流程负担 |
| 未完成份额仅由平台留存 | 新增“共同约池”双账本机制演示 | 让损失不只是一种惩罚，也成为认真履约者之间的连接 |
| 只显示个人退回 | 分开显示“个人本金预计退回 / 约池贡献 / 共同奖励资格” | 金额来源、去向和状态必须可解释、可审计 |
| 现实中断没有出口 | 每个七日周期一次暂缓，目标次数不减少、截止日顺延一天 | 给真实生活留缓冲，但不让补救机制消解承诺力 |
| 网站缓存可能保留旧壳 | Service Worker 缓存升级为 V3，同时兼容原 localStorage 键 | 桌面 PWA 更新后不丢用户已有任务 |

## 3. 共同约池规则：不可模糊的部分

### 双账本

```text
个人本金预计退回 = floor(承诺金 × 有效完成次数 ÷ 目标次数)
约池贡献         = 承诺金 - 个人本金预计退回
单人共同奖励预览 = floor(当期约池 ÷ 完整履约且通过复核的人数)
```

- 个人本金与共同奖励永远分账展示、分账记账、分账付款。
- 只有完成预先约定目标次数、无争议且验证合格的标准计划获得一份共享资格。
- 每名合格者一份，不按金额、连续天数或排名加权。
- 不能均分的余分冻结待处理，不随机发给某人，也不自动滚成“更大下期奖池”。
- 无人达标时整池冻结并进入人工/合规处理，不自动制造大奖。
- 暂缓须在截止前使用，每七日一次，只顺延一天、不降低目标数。
- 补做可以修复行动记录，但不能倒改已经封账的资金结算或共享资格。

### 当前为什么必须写“机制演示”

真实奖励尚未开放，因为当前系统仍缺少：

1. 不可覆盖的服务端打卡事件与统一完成证据；
2. 支付回调后由服务端激活计划，而不是前端本机状态；
3. 持久订单、约池批次状态机和幂等结算；
4. 12 小时故障/申诉冻结与人工复核；
5. 跨用户奖励付款、实名风控、对账、发票和税务方案；
6. 法律、微信支付规则与小程序审核结论。

微信“原路退款”只能退给原付款人，不能伪装成给另一名用户发共同奖励。

## 4. 设计不可破坏的原则

### 必须保留

- 首页第一层永远是“今天做什么”，不是钱、社交或统计。
- 打卡是一触完成；完成后直接结束，不弹评价、奖池、彩带或分享。
- 反馈、随记、复盘都由用户主动进入。
- 普通目标默认确定；验证只是可发现但不抢眼的次级能力。
- 任务时间和出现日随时可改。
- 钱的语言中性、透明、可审计：预计退回、约池贡献、共同奖励、冻结。
- 深墨绿、暖灰、酸橙绿的克制视觉可延续，但不要求机械保留现有组件。

### 必须删除或禁止

- 排行榜、赢家头像瀑布、奖池倒计时、中奖概率、随机抽奖；
- “瓜分、赢钱、翻倍、大奖、手慢无、血亏”等赌场化文案；
- 邀请返现和现金裂变；
- 每个页面都用大圆角卡片、玻璃拟态、渐变光晕和悬浮胶囊；
- AI 机器人头像、AI 教练聊天框、自动生成的励志废话；
- 为了“有趣”增加宠物、积分商城、勋章墙或连续打卡绑架；
- 强制写 Why、强制评分、强制复盘、强制社交；
- 把暂缓做成可购买道具，或让高金额用户获得更多容错。

## 5. 请你反向审查，而不是顺着现稿美化

请假设当前团队已经爱上自己的方案，你的职责是找出盲点。重点回答：

### A. 产品结构

1. 今天页的信息优先级是否仍然过多？共同约池应该再弱一点还是在关键时刻更强？
2. “编辑 / 记一下”是否让任务卡变得像后台管理？有没有更原生、更少文字的做法？
3. 自定义时间、每周出现日与默认模板怎样共存，才能让新手 10 秒完成、老用户仍有自由？
4. 一次暂缓应该在什么情境被发现，既不会被忘记，也不会成为默认逃生门？
5. 计划结束时怎样同时呈现“行动结果”和“三个资金账”，又不把钱变成主角？

### B. 有趣但不变味

1. 不靠排行榜、抽奖、宠物和强社交，产品还能通过什么微交互产生期待？
2. 共同约池怎样体现“有一群人在认真做各自的事”，而不是“陌生人在赌谁失败”？
3. 可以设计哪些低打扰连接点：例如匿名同伴数量、同一时刻开始、计划结束后的共同痕迹？
4. 哪些连接点能长期成立，哪些只会带来三分钟新鲜感？
5. 哪种完成反馈能强化能力感和自主感，而不是只强化金钱？

### C. 信任与边界状态

请逐页补齐至少这些状态：

- 无任务、无计划、离线、云同步失败；
- 支付中、支付取消、支付成功但计划未激活；
- 打卡已完成、撤销完成、截止后到达、证据待复核；
- 暂缓可用、已用、过期不可用；
- 约池开放、锁定、申诉中、待付款、已结算、异常冻结；
- 无人达标、只有一人达标、余分不能均分；
- 奖励付款失败但本金退款成功；
- 用户退出、降档、毕业、不再需要金钱约束。

### D. 页面美学

1. 它是否真的像一款成熟手机 App，而不是压窄的网站？
2. 组件是否过度卡片化？哪些内容应改成列表、分组、分隔线或直接排版？
3. 信息密度、触控尺寸、动态字体、色觉与单手操作是否达标？
4. 哪些动效值得存在？请给出触发、时长、缓动与 reduced-motion 降级，不要只写“加动效”。
5. 请给出一套非 AI 模板感的视觉方向，而不是紫色渐变、玻璃卡片和通用插画。

## 6. 你必须交付的结果

不要先生成高保真图。请按顺序交付：

1. **反向审计摘要**：最危险的 10 个问题，按严重度排序；
2. **删除清单**：现在有哪些元素或功能应删、合并、降级；
3. **完整用户路径**：首次打开 → 建目标 → 支付 → 日常行动 → 暂缓 → 结算 → 下一期/毕业；
4. **页面状态矩阵**：每页正常、空、加载、失败、冻结、完成状态；
5. **三套“有趣但克制”的连接机制**：各写动机、交互、风险、为什么不会三分钟热度；
6. **逐页线框**：今天、添加/编辑、七日约、约池详情、记录、结算、我的；
7. **视觉系统建议**：排版、间距、颜色、图标、卡片使用上限、微动效；
8. **MVP / 后置 / 禁止表**：明确什么现在做、用户增长后做、永远不做。

每个建议都要回答三个问题：

```text
它解决哪个真实用户问题？
它增加了多少认知或操作负担？
它会不会让钱盖过用户真正想长期做的事？
```

## 8. 最后一条提醒

不要把“共同约池”当成产品全部。它只是帮助行动发生的一种承诺装置。真正的产品价值仍然是：让用户选出自己认可、具有长期复利的事，并在现实生活允许的节奏里持续行动。

请挑战当前方案，但不要为了显得有创意而推翻已经验证的简约原则；也不要把创始人的个人习惯直接过拟合成所有用户的默认答案。
